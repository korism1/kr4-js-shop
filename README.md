# Bootstrap Shop — контрольная работа №4

Тема «JavaScript: интерактивность, DOM, события, формы и валидация».

Основа проекта — ветка `main` [контрольной работы №2 на Bootstrap](https://github.com/korism1/kr2-bootstrap-shop/tree/c792c4fb8f19c60f2a7ad9a51fee4d0fca71ce87). Используются Bootstrap 5.3.8, стили, фотографии и три страницы моделей из КР №2.

## Запуск

Откройте `index.html` в браузере или запустите проект через Live Server в VS Code. Для загрузки Bootstrap через CDN нужен доступ к интернету.

## Практическая работа №15

В ветке `feature/js-basics` подключены `data.js` и `main.js` через `defer`, создан объект товара и написаны `formatPrice`, `calculateDiscount`, `calculateFinalPrice`, `getProductStatus` и `createProductSummary`. Результат функций выводится в Console и в учебный блок через `textContent`.

## Практическая работа №16

В ветке `feature/products-array` объект заменён массивом. В итоговом массиве восемь учебных комплектаций трёх исходных моделей. У каждой позиции есть `id`, `title`, `category`, `price`, `discountPercent`, `rating`, `isAvailable`, `image`, `description` и `detailsPage`.

- `getProductTitles`, `getAvailableProducts` и `countAvailableProducts` получают названия и сведения о наличии.
- `searchProducts`, `filterProductsByCategory`, `sortProductsByPrice` и `getPreparedProducts` готовят список товаров. Сортировка работает с копией массива.
- `findProductById`, `calculateTotalPrice` и `calculateAveragePrice` находят товар или рассчитывают статистику. Краткая статистика выведена на главной странице.

## Практическая работа №17

В ветке `feature/dom-events` каталог связан с массивом товаров. Карточки создаются через `createElement`, `classList`, `textContent` и `append`. Поиск сопоставляет часть названия без учёта регистра и крайних пробелов. Можно одновременно выбрать категорию и сортировку по цене или названию. После каждого изменения обновляются карточки и счётчик. При отсутствии совпадений отображается сообщение. Кнопки «Заказать» обрабатываются одним слушателем сетки и открывают форму с выбранным товаром.

Форма проверяет имя от двух символов, формат e-mail, 11 цифр телефона с начальной 7 или 8 и согласие. Ошибки и сообщение об успешной проверке показываются на странице. Обычная отправка формы отменяется через `preventDefault()`. Обработчики регистрируются через `addEventListener()`. Динамический текст выводится через `textContent`, который не интерпретирует строки как HTML.

## Практическая работа №18

В итоговый проект входит обязательная базовая часть КР №4. Самостоятельные доработки из раздела 9 методички отсутствуют.

### Проверка перед защитой

1. На главной откройте DevTools → Console и проверьте таблицу товаров и блок «Проверка JavaScript».
2. Введите в каталоге `ZENBOOK`, выберите «Ультрабуки Windows» и отсортируйте по убыванию цены. Должны остаться три карточки от 145 000 до 110 000 руб. При запросе без совпадений должны появиться пустое состояние и счётчик с нулём.
3. В DevTools → Sources поставьте точку останова в `updateCatalog` на строке с вызовом `renderProducts`. Измените запрос и проверьте `catalogState` и `preparedProducts`.
4. Попробуйте отправить пустую форму. Проверьте вывод ошибок. Затем введите «Тест», `student@example.org`, `8 (999) 123-45-67` и отметьте согласие. На странице должно появиться сообщение об успешной подготовке заявки.
